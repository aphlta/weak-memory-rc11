## 2.1 引言

共享内存并发程序的正确性高度依赖底层内存模型。C/C++11 以公理化方式给出原子访问、同步与数据竞争的语义；随后的研究指出原模型在顺序一致性（SC）原子与栅栏方面存在缺陷，并由 Lahav 等人提出 **RC11** 予以修复。围绕执行图探索，验证与模型检验工具需要在巨大状态空间中枚举读–写对应（`rf`）及修改序（`mo`）等关系。

本文的贡献不在于提出新的完整内存模型，而在于：在可实现、可陈述的 **RC11 核心子集**上，研究面向观察结局与布尔性质的状态空间约简，并给出可执行原型与实验证据。因此，本章先回顾公理化传统与相关工具，再明确本文语义对象的文献定位；下一章给出一致性谓词的形式化写法。

## 2.2 相关工作

### 2.2.1 C/C++11 与 RC11

Batty 等人将 C/C++11 并发语义表述为执行图上的关系约束：程序序 `sb`/`po`、读自 `rf`、修改序 `mo`、同步 `sw`、happens-before `hb` 等。Lahav, Vafeiadis, Kang, Hur, Dreyer（PLDI’17）的 **RC11** 在保留该传统的同时修复 SC 相关问题，并给出更清晰的 SC 约束（与 Power 等架构编译结果相关）。

本文采用该传统下的**子集**：保留 litmus 级消息传递、Store/Load Buffering、release–acquire、栅栏、简化 release sequence 与 RMW，以及存在性 `mo`/`SC` 检查；刻意省略 consume、thin-air、完整 `psc` 边集、CAS 失败路径等。对齐细节见第 2.3 节与对照表。

### 2.2.2 执行图探索与约简

弱内存验证常通过对候选执行（或等价的操作交错）做穷尽或符号搜索。状态爆炸主要来自读端对写端的组合，以及（若全称枚举）修改序的乘积。已有工作从偏序约简、睡眠集、对称约简、面向性质的切片等角度削减搜索。本文聚焦一类**性质感知**约简：仅对影响观察结局、断言、同步形状或数据竞争判定的读维做细粒度枚举，其余读维用存在性扩展恢复一致性；并在相关读内部进一步按**值维**压缩写身份枚举（第 4 章）。

### 2.2.3 与 herdtools 等工具的关系

herdtools 等可在体系结构 cat 模型上判定 litmus 弱态是否允许。本文原型面向 RC11 风格的 JSON 小程序与布尔性质检测，**不**与 herdtools 做语义互模拟；实验中仅用经典 MP/SB/LB 弱态做**定性同向**对照（第 6 章），以支撑教具级可信度，而非声称模型等价。

## 2.3 本文语义对象：RC11 核心子集

### 2.3.1 一句话定位

本文实现并研究的对象是：

> **面向约简研究的 RC11 风格核心子集**：原子顺序 + fence +（简化）release sequence +（简化）RMW + 存在性 per-location `mo`（Co*）+ 存在性 SC 全序（含 `fr`/`rb` 用途）+ 简化数据竞争检测；**外加**性质感知约简（定理 T2⁺⁺）。

它回答：「在该子集下，给定小程序的观察结局 / race / 断言是否成立，以及约简是否保持。」  
它不回答：「任意 C++ 程序是否符合完整 RC11。」

### 2.3.2 关系与对象对照

| 文献对象 | 文献含义（简述） | 本文原型 | 对齐程度 |
| --- | --- | --- | --- |
| 事件 \(E\) | 访问 / fence / RMW 等 | load/store/rmw/fence/assert | 部分：无 CAS 失败、无混合宽度、无 lock |
| `sb` / `po` | 同线程顺序 | 程序序边 | 对齐（含 fence） |
| `rf` | 读从哪次写取值 | 候选枚举 + 赋值 | 对齐意图；初值写为虚拟 init |
| `mo` | 每地址写的修改序 | 存在性拓扑见证 | 简化：不枚举全部 `mo` |
| `rb` / `fr` | \(\mathrm{rf}^{-1};\mathrm{mo}\) | 用于 SC 与 Co* | 部分：未导出全局关系对象 |
| `rs` | release sequence | 同线程后续写 + RMW 沿 rf 延长 | 简化子集 |
| `sw` | 同步 | RA + fence 核心模式 | 核心对齐；见下节 |
| `hb` | \((\mathrm{sb}\cup\mathrm{sw})^+\) | `po ∪ sw` 传递闭包 | 定义形状对齐 |
| `eco` | 扩展一致性序 | 未显式构造 | 省略 |
| SC / `psc` | SC 事件约束 | 存在性全序（含 fr） | 简化，非完整 `psc` |
| DRF / race | 数据竞争 | 非原子冲突且无 hb | 简化教学定义 |
| no-thin-air / consume | — | 无 | 未做 |

### 2.3.3 同步 `sw` 覆盖

本文显式支持：

1. release/SC 写被 acquire/SC 读读到（含读到 RS 成员）；  
2. release fence 与其后写、acquire 读的组合；  
3. 写与其后 acquire fence；  
4. release fence 与 acquire fence。

相对文献：RS 取可实现子集；不机械展开全文 `psc`；无 consume，故无依赖序导出的同步。

### 2.3.4 操作子集（语言层）

支持 `relaxed` / `acquire` / `release` / `acq_rel` / `seq_cst`、`fence`、固定新值的简化 RMW。不支持 CAS 失败路径、`consume`、混合大小与位域。输入为 JSON 事件序列，而非完整 C 经编译器降低后的全部行为。

### 2.3.5 子集选取原则

1. **足够**：MP/SB/LB、RA、fence、RS、RMW、SC 教具与约简实验可陈述。  
2. **可证明相对本器**：一致性谓词固定后，约简健全与相对完备可写（第 4 章）。  
3. **可扩展**：相关闭包与值维剪枝不绑死完整 `psc`。

完整 RC11 机械化或与外部工具的互模拟列为后续工作（见 S6 说明）。

## 2.4 本章小结

本章将本文定位于 Batty/Lahav 公理化传统下的**可实现核心子集**，并划清未覆盖边界。下一章给出在该子集上的执行与一致性谓词，作为约简理论的语义底座。

> 可引用句：本文不重新提出内存模型，而在 Lahav et al. RC11 所代表的公理化传统下，固定一个可实现的核心子集，并在该子集上研究观察结局保持的状态空间约简。
