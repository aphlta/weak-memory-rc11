# 开题报告

## 题目

面向 RC11 弱内存模型的并发程序自动验证与状态空间约简方法研究

## 一、选题背景与研究意义

现代处理器、编译器以及并发语言标准普遍采用弱内存模型，以获得更高的性能和更大的实现自由度。在这一背景下，并发程序的真实执行结果往往不再满足顺序一致性假设，程序可能出现超出简单线程交错语义的行为。尤其是在 C/C++11 并发语义建立之后，原子操作、同步关系和内存顺序有了较精确的语言级定义，但也使程序验证面临更复杂的语义负担。

传统并发程序验证方法大多建立在顺序一致性基础上，难以直接适用于弱内存环境。已有研究虽然从 axiomatic 和 operational 两条路线对弱内存模型进行了系统刻画，也提出了程序变换、抽象机器、执行图搜索等自动验证方法，但在执行状态空间过大、验证成本过高以及工具可扩展性不足等方面仍存在明显问题。因此，围绕弱内存并发程序的自动验证与状态空间约简开展研究，不仅具有形式化理论意义，也具有较强的工程应用价值。

从理论角度看，本课题有助于推动 weak memory 形式化语义从“可定义”进一步走向“可验证”；从工程角度看，本课题有望为并发库、底层系统代码和教学型验证平台提供一套兼顾形式化严谨性与工程可实现性的自动分析思路。

## 二、国内外研究现状

### 1. 弱内存模型的形式化研究

早期研究主要关注弱内存模型本身的概念、定义及其与顺序一致性的关系，如如何通过写缓冲、可见性顺序、同步约束和数据竞争自由等概念解释并发程序行为。随着研究深入，弱内存模型形式化逐渐发展为较完整的体系，形成了 axiomatic semantics、operational semantics 以及两者之间的对应与比较框架。

### 2. 语言级并发语义研究

在语言层面，C/C++11 并发模型是弱内存研究的重要里程碑。相关工作不仅给出了语言级原子操作、同步关系和内存顺序的形式化语义，还通过 operational 方式实现了与 axiomatic 描述的对应，使得程序执行可以被逐步构造和分析。这为自动验证与执行图搜索提供了基础。

### 3. 自动验证与工具化研究

围绕弱内存程序自动验证，已有研究提出了程序变换、执行图遍历、抽象状态构造以及工具支持等多种方法。这些方法说明弱内存验证在理论上和实现上都是可行的。然而，与顺序一致性下的验证相比，弱内存模型允许更多合法执行，因此状态空间膨胀问题更加突出，成为影响工具实用性的关键瓶颈。

### 4. 并发库与模块化验证

近年来，研究对象已从短小 litmus tests 逐步扩展到并发库、抽象数据结构和模块化组件。面向 C11-style weak memory libraries 的研究表明，仅对小程序逐一枚举合法执行已无法满足工程需要，更高层次的模块化推理和高效验证机制成为新的研究重点。

### 5. 现有研究存在的问题

综合来看，现有研究仍存在以下不足：

1. 弱内存下候选执行数量庞大，状态空间爆炸严重。
2. 一些验证方法实现复杂，难以形成轻量级原型工具。
3. 在 RC11/RA 这类代表性子模型上，仍缺少兼顾正确性、效率和扩展性的验证框架。

## 三、研究目标

本课题拟面向 RC11 弱内存子模型，研究并发程序自动验证与状态空间约简方法，重点解决执行图搜索规模过大、弱内存关系构造复杂以及验证效率不足等问题。

具体目标如下：

1. 构建适用于 RC11/RA 子模型的程序执行表示方法。
2. 研究弱内存执行图中的冗余来源并设计状态空间约简策略。
3. 实现支持数据竞争与断言违例检测的自动验证原型。
4. 通过 litmus tests 与小型并发 benchmark 对所提方法进行评估。

## 四、研究内容

### 1. 面向 RC11 的程序执行表示

围绕 RC11 子模型中的关键语义关系，建立适合自动验证过程的数据表示方式。重点包括程序事件建模、`reads-from` 关系、`modification order`、`happens-before` 关系以及候选执行图构造。与 Batty/Lahav 文献的子集对照见仓库 [`phd/RC11-ALIGNMENT.md`](../phd/RC11-ALIGNMENT.md)。

### 2. 弱内存执行图的状态空间约简

针对执行图生成中的冗余分支与等价执行，研究状态空间约简策略，在保持语义正确性的前提下减少需要探索的候选执行数量。该部分将作为本课题最主要的创新点。

**已形成的方法要点（相对本器语义，记为 T2）**：以观察变量集合 \(\mathsf{observe}\) 上的结局集合保持、以及 data race / 断言违例的布尔结论保持为目标；只显式枚举相关读的 `reads-from`，无关读做存在性一致扩展。独立性假设（IND）可用静态规则检查：违例读默认提升为相关（`promote`），或拒绝约简回退全枚举（`refuse`）。细节与引理见仓库 [`docs/REDUCTION.md`](../REDUCTION.md)；规模实验见 [`docs/benchmark_summary.md`](../benchmark_summary.md)。

### 3. 自动验证算法设计

为了控制课题范围，本文拟首先支持两类典型验证任务：

1. 数据竞争检测
2. 断言违例检测

在此基础上，进一步研究反例执行生成与结果输出机制。

### 4. 原型工具实现与实验评测

实现一个原型工具，支持小型并发程序输入、候选执行图构造、错误检测与结果展示。实验部分重点比较约简前后在运行时间、空间开销和错误发现能力上的变化。

**已有实验支撑**：噪声规模下 rf 组合缩减曲线；全量 vs 约简墙钟中位数（`scripts/bench_timing.py`）；噪声下弱态断言失败与 data race 仍可被约简模式检出；与 herdtools 经典 litmus 在 MP/SB/LB 上的弱态对照（见 [`HERD-COMPARISON.md`](../HERD-COMPARISON.md)）。博士阶段理论稿见 [`phd/THEORY-v1.md`](../phd/THEORY-v1.md)。汇总见 [`benchmark_summary.md`](../benchmark_summary.md)。

## 五、拟解决的关键问题

1. 如何在 RC11 子模型下构建既准确又便于实现的执行表示。
2. 如何识别弱内存执行图中的主要冗余来源。
3. 如何在不丢失合法反例的前提下实现有效约简。
4. 如何将理论模型落地为可运行的自动验证原型。

## 六、研究方法与技术路线

本课题采用“先缩小问题范围、再研究执行约简、最后完成原型验证”的技术路线，具体步骤如下：

1. 选定 RC11/RA 弱内存子模型。
2. 建立程序到候选执行图的形式化映射。
3. 分析执行图中的冗余分支与等价搜索路径。
4. 设计状态空间约简策略。
5. 实现自动验证算法与原型工具。
6. 使用 litmus tests 与 benchmark 进行实验评测。
7. 形成论文和答辩材料。

## 七、创新点

1. 面向 RC11 子模型，构建一种适合自动验证过程的执行表示方法。
2. 提出一种针对弱内存执行图的状态空间约简策略（观察结局保持 + 可检查 IND），以降低验证开销。
3. 设计并实现支持数据竞争与断言违例检测的原型工具，并通过含噪声规模曲线的 benchmark 验证其有效性。

## 八、可行性分析

### 1. 研究对象可控

本课题选择 RC11/RA 子模型作为研究对象，能够显著缩小问题范围，避免一开始即面向完整 C/C++11 语义所带来的复杂边界问题。

### 2. 理论基础充分

弱内存模型的形式化定义、语言级并发语义、自动验证思路和执行图分析方法均已有较多研究成果，可直接作为本课题的理论基础。

### 3. 工程目标适中

原型工具只需面向小型并发程序与典型原子操作，即可形成较完整的硕士论文成果，具备较强的实施可行性。
